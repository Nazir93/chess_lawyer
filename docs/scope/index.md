# Scope: Lawyer Chess Club

Закрытая цифровая среда шахматного клуба юристов Москвы: Telegram Mini App и PWA для членов (одна кодовая база, один аккаунт по Telegram), Telegram бот для уведомлений и веб панель для администраторов. Вступление только по приглашению, 50–100 членов на старте, ориентир до 1 000. Срок 10–12 недель.

**Build approach:** Tracer Bullet (каждый срез сквозной: БД → API → Mini App / бот / админка, узкий, но настоящий; следующий срез утолщает уже работающую нить).
**Workflow:** GA (после `/develop`: `/check verify`, `/test`, `/check review` свежей моделью, `/document`). Причина: персональные данные по 152-ФЗ, RBAC, атомарная запись, рейтинг с аудитом и сдача проекта заказчику с приёмкой.

Источник требований: [docs/product/tz.md](../product/tz.md) (версия 1.1). Референсы дизайна: [docs/design/references/](../design/references/). Открытые решения: [docs/product/open-questions.md](../product/open-questions.md). Словарь терминов: [GLOSSARY.md](../../GLOSSARY.md).

_Это рекомендации, чтобы сборка шла по порядку, а не требования. Если ты уже знаешь, как строить фичу, можно сразу `/develop` и пропустить `/architect`. Когда фича `done`, решаешь ты._

## Legend

**Решающий пункт (decision box).** У каждой фичи ровно один пункт, чья подпись заканчивается на `(spec)`. Скиллы находят его по этому суффиксу. Остальные пункты исполнительные, `/architect` их не отмечает.

| Состояние | Кто ставит | Что видно у фичи |
|---|---|---|
| `planned` · needs a decision | `/scope` | один пункт: `Design it (spec): /architect <feature>` |
| `in-progress` (спроектирована) | `/architect` при записи спеки | `Design it` отмечен; ссылка на спеку; `Build it: /develop <feature>` + 2–5 вех; `Verify it`, `Test it`, `Review it`, `Document it` (GA) |
| `in-progress` (строится) | `/develop` | вехи отмечаются по одной; путь к коду заполнен |
| `done` | ты, когда решишь; `/sync` сверяет | для GA подсказка: после `/test` |

- **Следующий шаг** всегда первый неотмеченный пункт.
- **needs a decision**: сначала `/architect`; метка снимается, когда спека записана.
- **Атомарные задачи сборки** живут в `## Build plan` спеки, здесь только вехи.
- **Статусы:** `planned` → `in-progress` → `done`, плюс `dropped` (исключено, хранится для истории).
- **Тег уровня** у заголовка (например `· Beta`) меняет строгость одной фичи; без тега наследуется GA.
- **Строка указателей** (`spec <n> · code in <path>`) появляется, только когда спека и код существуют.
